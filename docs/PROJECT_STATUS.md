## 7. 移交、暂停、回到本团队的规程

每一次**转出、暂停、恢复或回到本团队**，都必须先更新本文（至少第 1–3 节与第 8 节日志），然后才能继续实质性工作。不要依赖未入库的私有路径、聊天记忆或机器上未提交的构建树。禁止写入密钥、账号细节或用量数据。

恢复工作的 agent（无论是外部接手人还是原团队）必须**先**：

1. `git fetch`，核对远端 `main` 与本文记录的 SHA 是否仍一致（或已有更新）。
2. 对照第 8 节日志，把已完成项、进行中项与测试/CI 状态写进本快照；**不要重复已完成（含已 Closed）的工作**。
3. **不要假定**运行时状态、本机 `build*` 目录、工作区或测试进程仍然存在。
4. 在第 8 节追加一条日志后再动手。若只是文档对账，也先改记录再改其它文件。

每条日志应包含：

- **所有者**（MIN YE）与记录人；
- **日期与时间**（Asia/Shanghai）；
- **分支与提交**（远端 `main` 与本地工作提交，注明是否已推送）；
- **已完成 / 进行中**；
- **测试与 CI**（已核实的 URL 或明确“未跑 / 仅报告、未核实”）；
- **下一步**；
- **未决选择**；
- **转出方与接入手的所有权确认**（未指定则写“待 MIN YE 指定”，不得留空或编造姓名）。

回到本团队时：同样先对账再工作；原团队不得在未读本快照的情况下重做已交接内容，也不得把未推送的本地提交当成远端事实。
